# Publish Pennino v0.4.27

- Goal: ship one-finger panning with the hand tool and the page number pinned
  to the view's corner, and publish the binaries.
- Owner: Qoder.
- State: release published from `05cc57b`; assets verified from their
  downloaded bytes (see Proof below).

## Log

- One behaviour pair separates this tag from `v0.4.26`. PR #62 (`aaa8a7b`)
  makes the hand tool selectable in both tool rows, pans the paper with one
  finger through the same viewport rule the wheel and the pinch use, and moves
  the page number off the paper to a fixed chip in the view's top-left corner.
  PR #63 (`e82f1e9`) is the version bump and nothing else. The design, the
  nine checks and their mutation proofs are in
  [hand-pan-and-pinned-page-number](./2026-11-14-hand-pan-and-pinned-page-number.md);
  this note records the release.
- The release goes out over the same seam as the last three, because branch
  protection needs a commit CI already accepted on all three jobs: bump PR
  green on its own head, merge, post-merge main green, and only then an
  annotated tag at exactly that commit - the workflow that signs binaries
  fires on a tag and on nothing else.
- What a phone user is told about this release, measured rather than assumed:
  the GitHub release body is the tag workflow's generated `## What's Changed`
  notes with a compare link. `fastlane/metadata/android/en-US/changelogs/31.txt`
  is store-facing copy for whoever publishes to a store; no code or workflow
  in this repo reads it.

## Don't repeat

- `flutter test` does not run `widget_test/editor_gesture_test.dart`; CI runs
  it on its own line. The first run of this PR failed there because two of its
  premises - no Hand tool, one chip per page - were exactly what the change
  removed. Run that file locally with the rest of the gate.
- Same APK length is not the same build: `v0.4.24` through `v0.4.27` all carry
  a 6,095,752 B arm64 snapshot. Ask for a literal only the new release
  contains.
