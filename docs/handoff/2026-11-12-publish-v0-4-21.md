# Publish Pennino v0.4.21

- Goal: Ship one global text document per note in place of the many canvas text blocks, and release it.
- Owner: Qoder.
- State: Published. Tag `v0.4.21` at `38075fe`, both assets live. Two follow-up editor fixes are open in PR #32, unmerged.

## Log

- User decisions that shaped the change: the text layer stays visible and interactive; a note's existing blocks concatenate into the single document on its next save; the document sits in a fixed column at the top of the page; a tap that misses the glyphs draws, like paper.
- Design recorded in [single-text-document-design](./2026-11-12-single-text-document-design.md), then planned and implemented test-first.
- PR #30 "One global text document per note" carried three commits: store one document per note (`9bdfffc`), edit it in a fixed column at the top of the page (`aa8d0d2`), and rewrite the README and design record (`87ed662`). Merged as `7f002e2`.
- `Note.currentFormatVersion` stayed at **7**. The document lives in `Note.text`; `_documentFromBlocks` in `lib/note_data.dart` folds a legacy note's blocks into one document, shifting every formatting offset by the earlier blocks plus the two-character separator that joined them, so no format bump and no forced migration were needed.
- `RichTextEditingController.buildTextSpan` must be given `style:` — without it the span measures at 14pt and the stored formatting ranges are dropped.
- PR #31 "Release v0.4.21" (`3cd3d5b`) bumped the version and merged as `38075fe`.
- After the release the user reported the Android home-screen widget broken. Root cause, proven with a probe rather than inferred: `renderPreview()` never painted the text document, so a typed note's preview was byte-identical to a blank one (2289 B, 700×420) while the controller held text. A drawn preview differed (2540 B), which isolated the gap to text. Ten prior versions were checked and none painted text — a long-standing gap that the single-document refactor made dominant, because typed content is now the whole document. No test covered the path.
- The user also asked for the eraser to "work as blur but erasing", clarified to a soft feathered edge. The eraser cut a hard edge while blur softened its band. Both halves now share one ramp, `strokeFeatherPasses` in `lib/canvas_painter.dart`: the live overlay lays down paper through it, and the bake accumulates it into a layer composited with `BlendMode.dstOut`, leaving destination alpha × Π(1−oᵢ) — the same fade the overlay showed. `RasterDrawingPainter.activeEraser` was deleted with its hard-clear branch, so a mark cannot be erased twice.
- Both fixes are in PR #32 (`880fad6`), test-first: `eraser feathers the mark instead of cutting a hard edge` probes alpha at 0/8/14/20 px from the brush centre and requires a gradient a hard edge cannot produce; `the home widget preview shows the typed document` asserts the ink's bounding box, not just its presence, so a missing page-scale transform fails it. Local gates on that branch: `flutter analyze` clean, `flutter test` +23, `widget_test/editor_gesture_test.dart` +34.

## Don't repeat

- Do not create a release tag before the post-merge `main` workflow passes, and never re-tag `v0.4.19`, `v0.4.20` or `v0.4.21`.
- Do not upload local build artifacts; the release workflow signs with the configured Android secrets.
- Do not call `buildTextSpan` without `style:` — the document silently loses its formatting ranges.
- Do not gate a block's pointer behaviour on `activeTextIndex` alone; `_selectTool` leaves it set after leaving the text tool.
- Do not run a verification gate through a pipe: `cmd | tail` reports the pipe's exit code and has already masked a failed build once. Use `cmd > log 2>&1; echo "exit=$?"`.
- A green CI run is evidence a merge *can* happen, never that it *may*. Each merge needs the user's explicit word, as its own call — never chain `PUT /pulls/N/merge` onto a mergeability probe, and never use the merge endpoint to refresh a `mergeable: null` verdict; re-read with `GET /pulls/N`.
- Leave unrelated untracked `.codex/`, `reports/`, `research_notes/` and `docs/superpowers/` untouched.
