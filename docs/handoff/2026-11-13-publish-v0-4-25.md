# Publish Pennino v0.4.25

- Goal: ship the home-screen widget fix that merged after v0.4.24 and publish
  the binaries.
- Owner: Qoder.
- State: release published from `59c7fe8`; assets verified from their
  downloaded bytes (see Proof below).

## Log

- Three PRs merged into main between `v0.4.24` and this tag, and only one of
  them changes what the app does: PR #55 (`c38c4fc`) pins the page that has
  ink, PR #54 (`0a9da49`) and PR #56 (`b4eaa4f`) replace two load-sensitive
  fixed waits in the test suite with condition waits. The changelog for
  version code 29 says the widget part, because that is what a phone user
  will notice.
- The widget bug came in as "widget is not working on android" and was
  narrowed with the reporter to an empty card. The packaging was ruled out
  against the released v0.4.24 APK first (`aapt dump xmltree`, `dexdump`,
  resource table), then the fault was found in the Dart capture: the preview
  painted page zero only. Details in
  [pin-the-page-that-has-ink](./2026-11-13-pin-the-page-that-has-ink.md).
- The drive-sync flake was not hypothetical: `v25_test.log` holds the failing
  run from the first attempt at this bump, both tests at
  `Expected: <1> / Actual: <0>` with a Gradle daemon running alongside. That
  is why the wait fix went in before the tag rather than after it - the
  release gates on this machine cannot be trusted to be green twice in a row
  while it is compiling.
- `flutter build apk --release` refuses to run on this machine and that is the
  designed behaviour, not a regression: "android/key.properties is missing, so
  release builds cannot be signed. Refusing to fall back to the debug signing
  config: a debug-signed release APK cannot be installed over previous
  releases." The signed binaries therefore come only from this tag workflow.
- The merge endpoint answered `422 Unprocessable Entity` on PR #56 when the
  `sha` was passed truncated to the short form the CI watcher prints. That is
  a request-shape failure, not a merge failure: re-reading `GET /pulls/56`
  showed the PR still open with its full head sha, and the same call with the
  40-character sha merged. Truncating a sha proves nothing about the state of
  the object it names.
- `watch_main.py` died once on a `BrokenPipeError` from the HTTPS GET, and the
  background wrapper still reported exit code 0 - the log, not the exit code,
  is the evidence. The watcher now runs behind a retry loop.

## Don't repeat

- Do not pass a truncated sha to `PUT /pulls/N/merge`; it answers 422 and the
  PR stays open. Read the head sha from the PR rather than from a log line.
- Do not read a background wrapper's exit code as the watcher's verdict. A
  network exception inside the script leaves the log as the only evidence.
- Do not let an unchanged artifact size talk you out of a release: two
  consecutive Pennino APKs here are the same total length with the same
  per-entry lengths, and only a content marker inside `libapp.so` and the
  ancestor checks distinguish them. The digest already did; the size would
  have fooled nobody only by luck.
