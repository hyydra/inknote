# Publish Pennino v0.4.22

- Goal: Ship the feathered eraser and the home-widget preview fix, and release them.
- Owner: Qoder.
- State: Published. Tag `v0.4.22` at `bb610a5`, both assets live and their digests verified.

## Log

- The user asked for the eraser to "work as blur but erasing", clarified to a **soft feathered edge** — not erasing typed text, and not merely restructuring the layer.
- The eraser cut a hard edge while blur softened its band, so the two felt like different tools. One ramp, `strokeFeatherPasses` in `lib/canvas_painter.dart`, now drives both halves: the live drag overlay (`_eraseStrokeLayer` in `lib/main.dart`) lays down bare paper through blur's widths and opacities, and the raster bake in `lib/raster_drawing.dart` accumulates the same ramp into a layer composited with `BlendMode.dstOut`. Remaining destination alpha is × Π(1−oᵢ), which is exactly the paper coverage the overlay showed, so the preview and the bake cannot drift.
- `RasterDrawingPainter.activeEraser` was deleted along with its hard-clear branch, so a mark cannot be erased twice. The widest feather pass is width×1.1, so the erase bounds inflate by `width * 0.6 + 1` rather than the old `width / 2 + 1`.
- The user then reported the Android home-screen widget broken. Root cause proven with a probe, not inferred: `renderPreview()` never painted the text document, so a typed note's preview was byte-identical to a blank one (2289 B, 700×420) while the controller held text; a drawn preview differed (2540 B), isolating the gap to text. Ten prior versions were checked and none painted text — a long-standing gap the single-document refactor made dominant, because typed content is now the whole document. No test covered the path.
- Fix: paint `_layoutDocument()` at the page's own scale (`size.width / canvasWidth`, `size.height / canvasPageHeight`), offset by `_documentPageMargin + _textContentLeft` and `_documentPageMargin + _documentContentTop`. The preview is a fixed `Size(700, 420)` over a 2000×1200 page, so the scale is 0.35.
- Both fixes went in test-first as PR #32 (`880fad6`), merged as `784b600`. The eraser spec probes alpha at 0/8/14/20 px from the brush centre and requires a gradient a hard edge cannot produce; the preview spec asserts the ink's bounding box, not just its presence, so a missing scale transform fails it (canvas (56, 52) × 0.35 ≈ (20, 18)).
- PR #33 recorded the v0.4.21 publish. Main protects with `strict: true`, so merging #32 made #33 `behind` and its earlier green run no longer counted. Its branch was updated with main (`3c8f2ad`), re-gated, confirmed `clean`, then merged as `bbcb6f4`.
- PR #34 (`1d5a5d9`) bumped `pubspec.yaml` to `0.4.22+26` and `lib/app_version.dart`'s default to `0.4.22` — the same two-file shape as `3cd3d5b` — and merged as `bb610a5`. `release.yml` injects the version from the tag (`GITHUB_REF_NAME` minus `v`) into both builds and the Inno Setup installer, so the tag wins at release time; the source default only serves local builds.
- Local gates on the bump tree, each run without a pipe so its own exit code was visible: `flutter analyze` exit 0 ("No issues found! (ran in 2.5s)"), `flutter test` exit 0 (`+23`), `flutter test widget_test/editor_gesture_test.dart` exit 0 (`+34`).

## Don't repeat

- Main's protection is `strict: true` with required contexts `android`, `linux`, `windows`. Merging one PR stales the next: re-read `mergeable_state`, update the branch with main, and re-gate CI. A green run on an outdated branch does not count.
- Do not create a release tag before the post-merge `main` workflow passes on the exact release commit, and never move, delete or re-tag `v0.4.19`–`v0.4.22`.
- `mergeable: null` only means GitHub is still computing — re-read the same `GET /pulls/N`. Never call `/pulls/N/merge` to nudge a verdict, and never chain a merge onto a mergeability probe.
- A green CI run is evidence a merge *can* happen, never that it *may*; each merge needs the user's explicit word.
- Do not upload local build artifacts; the release workflow signs with the configured Android secrets.
- Do not call `buildTextSpan` without `style:` — the document silently loses its formatting ranges.
- Do not run a verification gate through a pipe: `cmd | tail` reports the pipe's exit code and has already masked a failed build once. Use `cmd > log 2>&1; echo "exit=$?"`. A background wrapper's exit 0 likewise only reflects its last command — read each gate's own code.
- Leave unrelated untracked `.codex/`, `reports/`, `research_notes/` and `docs/superpowers/` untouched.
