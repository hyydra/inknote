## Log

- The whole-repo review produced eleven fix branches, opened as PRs #36-#46 and merged into protected main one at a time through `android`/`linux`/`windows`, in dependency order: #36 tombstones so deletes propagate, #37 refuses unsigned releases and makes the Windows installer single-instance, #38 classifies a pinch by its whole frame so zooming cannot append a page, #39 reports an unreadable note folder and makes the upgrade copy crash-safe, #40 bounds the update download and lets the user stop it, #41 autosaves every edit and refuses to close on an unwritten note, #42 undoes and redoes the marks on the paper, #43 fades a blurred mark out over the band the preview shows, #44 decodes raster tiles only when the paper or a stroke needs them, #45 keeps the toolbar rows inside the window they were given, and #46 clears the stale copies the release metadata left behind.
- Merging was serial, not parallel: main requires the three checks to be green on a head that already carries main, so each merge moved the goalposts for the next one and every PR needed `PUT /pulls/N/update-branch` before it could pass.
- Two conflicts were semantic rather than textual. Stacking #42 (undo/redo) onto main put undo and redo buttons in the app bar, which overflowed by 30 px at 240 px wide - the layout test only reached that width once those buttons existed. And #41, #42 and #43 each carried their own copy of `pumpUntilTrue`, whose wait was bounded by 60 pump turns; on a slow runner sixty turns ran past the six seconds of fake time the assertion demanded. All three now bound the wait by a wall clock as well as a turn count.
- `tester.binding.setSurfaceSize` constrains layout but leaves `MediaQuery` reporting the 2400×1800 physical test default, so a "narrow" test screen asked the app bar for its wide layout while fitting 240 px of it - a pairing no device can produce. `test/layout_and_theme_test.dart` now sets `tester.view.physicalSize` and resets it in `addTearDown`, which moves the constraints and `MediaQuery` together.
- PR #48 "Release v0.4.23" (`67d848d`) bumped `pubspec.yaml` to `0.4.23+27` and the `appVersion` fallback to `0.4.23`, and added `fastlane/metadata/android/en-US/changelogs/27.txt`. Merged as `924ca0f`.
- `android/app/build.gradle.kts` reads `flutter.versionCode`/`flutter.versionName` and the Windows resources read `FLUTTER_BUILD_NAME`, so pubspec is the only source of truth for a bump; nothing else needed editing.
- PR #35 "Record the v0.4.22 release" was closed as superseded; this note replaces it.
- PR #47 "CI platform coverage" is deliberately still open. It records where the test coverage actually is - the windows job builds without analyzing or testing, one suite runs only in the android job, and six files in `test/` are plain scripts whose PASS lines the runner never counts - and three of its four patches edit `.github/workflows/`, which this credential cannot push.

## Don't repeat

- Tag after the post-merge main run passes, not beside it. Here the tag went up while `43451126906` was still in flight; both ran the same commit and both passed, so nothing was published blind, but the ordering rule exists for the case where they disagree.
- Do not read a green CI run as approval to merge. Each merge here was preceded by the user's explicit "fix and build and deploy" and the release scope chosen with them.
- `PUT /repos/{owner}/{repo}/pulls/{n}/merge` is the merge endpoint - POST and PATCH answer 404. `mergeable` comes back `null` right after a merge because GitHub computes it lazily; re-poll `GET /pulls/{n}` rather than treating null as a conflict.
- Job logs and release asset downloads redirect to object storage that rejects the `Authorization` header. Follow the redirect by hand and fetch the target unauthenticated, or a 401 looks like a missing secret.
- Do not run a verification gate through a pipe: `cmd | tail` reports the pipe's exit code and has masked a failed build before. Use `cmd > log 2>&1; echo "exit=$?"`.
- The six plain-script files in `test/` were never `package:test` and never shared a `test/_harness.dart`; a handoff note that claims the harness went missing is describing a file that does not appear in any commit. Their real problem is that the runner cannot see their assertions.
